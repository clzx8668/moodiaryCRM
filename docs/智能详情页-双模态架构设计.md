## 0. 一页速览

**本设计要回答的问题**：点击首页任意记录后，进入的"中间详情页"应该长什么样、怎么工作。

**答案（一句话）**：中间详情页 = 一条记录的**智能卡片栈**。记录本身是第一张卡，之后每次追加笔记、每次 AI 处理，都变成后续的卡；每张卡底层是一个 JSON Block（真相层），上层渲染出 Markdown / 表单 / 待办等可交互形态（投影层）；点击卡片按内容类型路由到 Markdown 编辑器或表单编辑器。

**四条核心决策**：

1. **一张智能卡片 = 一个 Block**，复用现有 `Blocks` 表，不新建"卡片表"（避免过度设计）。
2. **双模态**：JSON Blocks 是唯一真相层；Markdown 是派生投影层（阅读/导出/搜索/向量化都走投影）。
3. **卡片点击走策略路由表**（`CardActionRouter`）：文档类 → Markdown 编辑器，实体类 → 表单页，待办 → 原地勾选，图片 → 全屏预览；新增卡片类型只需注册一行。
4. **状态五层独立**（BlockList / Streaming / Edit / Search / Sync），严格对齐架构文档 6.2，杜绝单一大 Controller。

## 1. 闪念贝壳调研结论（设计依据）

"闪念贝壳"在公开资料中有两个对应物，均有参考价值，本设计取其交集：

### 1.1 Blinko（开源，blinkospace/blinko）

本地已有一份完整源码（`E:\Dev\blinko`），直接研读了核心实现：

| 可借鉴点 | 源码依据 | 本设计的落点 |
| :-- | :-- | :-- |
| 卡片即内容单元，支持展开/收起（移动端全屏展开动画） | `BlinkoCard/index.tsx` + `expandContainer.tsx` | 卡片容器 `SmartCard` 带展开/收起态 |
| 长文自动识别为"文章"，点开进入全屏阅读/编辑 | `BlinkoCard/index.tsx`（`isBlog` 判定） | 文本卡超过阈值自动折叠 |
| 全屏编辑器：预览/编辑双模式，ESC 逐级回退（编辑→预览→关闭），双击切换 | `FullscreenEditor.tsx` | Markdown 编辑器复用现有 edit 页，增加"按卡片编辑"模式 |
| 卡片头部：时间/类型/置顶/删除；底部：类型转换（Blinko↔Note↔TODO） | `cardHeader.tsx` / `cardFooter.tsx` | 卡片头部来源徽标 + 操作菜单；卡片可"转待办" |
| AI 输入条常驻，支持 RAG 开关、@引用笔记、流式回答、引用溯源卡片 | `BlinkoAi/aiInput.tsx`、`aiChatBox.tsx` | 详情页底部追加输入条；AI 卡片流式渲染 + 引用溯源（Phase 3） |
| 流式渲染节流（80ms + RAF），避免整页重绘 | `aiChatBox.tsx`（`StreamingAiMessage`） | Flutter 侧用节流定时器刷新流式卡片 |
| AI 回答可一键"加入闪念/加入笔记" | `aiChatBox.tsx`（AiMessage 操作） | AI 卡片完成后可"转正"为 text/todo/smartEntity |

### 1.2 闪念贝壳 App（IdeaShell，广州圆红点科技）

公开介绍（应用商店/资讯页）提炼出的产品逻辑：

- **语音转录 + AI 优化**：口语→文字→自动标题/摘要/分段/标签。
- **AI 讨论**：基于一条灵感与 AI 多轮对话，过程中回抛"回顾卡片"。
- **AI 创作生成智能卡片**：内置创作指令模板（待办事项/总结摘要/邮件草稿/视频脚本/工作报告/创意提案），产出即卡片、可自定义。
- **智能卡片导出生态**：卡片可导出到 Notion/Craft/WPS/Word 等。
- **闪问 AI**：自然语言检索个人笔记（RAG），回答可一键存为新笔记。

**对本设计的启示**：模板化 AI 处理（待办/总结/扩写/润色/翻译/会议记录）的产物应以"卡片"形态追加进详情页，且卡片应可自由转成待办/笔记等类型——这与 moodiaryCRM 快速收集面板已留的"模板 AI 占位钩子"完全同构。

### 1.3 结论：详情页工作模式

```
首页（列表/网格/块视图）
  └─ 点击任意记录
       └─ 中间详情页 = 智能卡片栈
            ├─ 卡1  原始记录（继承首页内容）      ← text block（source=initial）
            ├─ 卡2  追加笔记                      ← text block（source=appended）
            ├─ 卡3  AI 处理结果（流式→转正）      ← aiStream→text/todo/smartEntity
            └─ 卡N  …以此类推
                点击卡片：
                 ├─ 文档类（text/code） → Markdown 编辑器（全屏）
                 ├─ 实体类（smartEntity）→ 表单编辑器（全屏）
                 ├─ 待办（todo）         → 原地勾选
                 ├─ 图片（image）        → 全屏预览
                 └─ 图表（chart）        → 图表查看
```

## 3. 双模态数据架构

### 3.1 分层定义

```
┌─ 展现层（Markdown 投影）─────────────────────────────┐
│ 阅读渲染 / 导出 / 全文搜索 / 向量化输入 / 分享        │
└──────────────────────▲──────────────────────────────┘
                       │ 投影（纯函数，只读派生）
┌─ 真相层（JSON Blocks）───────────────────────────────┐
│ Blocks 表：type + content(JSON/Markdown) + meta       │
│ AI 解析 / 结构化交互 / 同步 / 冲突解决 都以它为真相   │
└──────────────────────────────────────────────────────┘
```

- **真相层**：`Blocks` 表（已有），所有写操作先落这里；AI 输出、实体编辑、待办勾选都改 Block。
- **投影层**：`markdownProjection(Block) -> String` 纯函数，把任意 Block 投影为 Markdown。
- **聚合规则**：`diary.contentText = 未删除 Block 按 sortOrder 投影后以 '\n\n' 拼接`。首页列表、搜索、导出不再直接读 `diary.content`，而是读聚合结果（保留 `content` 字段兼容上游，写入时同步刷新）。

### 3.2 Block 协议扩展（v3 → v4 迁移）

现有 `Blocks` 表字段齐全，仅缺**业务元数据**。新增一列（幂等迁移 + 迁移日志）：

```sql
ALTER TABLE blocks ADD COLUMN meta_json TEXT NOT NULL DEFAULT '{}';
```

`meta` 内容（JSON）：

```json
{
  "source": "initial | appended | ai | imported",
  "syncStatus": "synced | pending | conflict",
  "aiTemplate": "summary | expand | polish | translate | meeting | todo",
  "entityType": "company | person | opportunity | task",
  "title": "卡片标题（可选，用于折叠态）"
}
```

- `source=initial`：首页继承的原始记录卡（第一张卡）。
- `source=appended`：详情页内追加的笔记卡。
- `source=ai`：AI 处理产物卡（未转正前 type=aiStream）。
- `source=imported`：旧数据/外部导入。

对应模型改动：`Block` 增加 `metaJson` 字段 + `BlockMeta` 便捷读写（`lib/features/block/models/block_meta.dart`），Drift `Blocks` 表加列，`migration.dart` 增加 v3→v4。

### 3.3 Markdown 投影函数表

| BlockType | 投影规则 | 示例 |
| :-- | :-- | :-- |
| text | content 原样 | `今天约了张三聊合同…` |
| code | ```` ``` ```` + content + ```` ``` ```` | |
| todo | `- [ ]/[-x] 文本`（done 取 content 前缀标记） | `- [ ] 下周三寄出样品` |
| smartEntity | `**实体**：名称 · 状态`（JSON 解析成摘要） | `**客户**：张三 · 跟进中` |
| image | `![](相对路径)` | |
| chart | JSON 摘要为一行标题 + 数据点 | `**图表**：月度回款 3 项` |
| aiStream | 完成态用 content；未完成用 streamBuffer | |

实现为纯函数文件 `lib/features/block/markdown_projection.dart`，配套单测（每种类型 ≥3 用例）。这既是**导出/分享/搜索的统一入口**，也是**向量化（RAG）的输入源**——为遗留项 4 铺路。

### 3.4 双模态写入路径

```
追加笔记/编辑卡片/勾选待办/AI 转正
  → 写 Blocks 表（真相层，乐观更新，syncStatus=pending）
  → 重算 diary.contentText（聚合投影，同步刷新）
  → 触发 Rust 同步/向量索引（事件流，遗留项 3/4）
```

## 4. SmartCanvasPage 交互设计

### 4.1 页面布局（信息架构）

```
┌─────────────────────────────────────┐
│ SliverAppBar  标题/心情/时间/标签    │  ← 复用现有 DiaryDetailsPage 头部
├─────────────────────────────────────┤
│ 卡片栈（竖向，可滚动）               │
│  ┌───────────────────────────────┐  │
│  │ 卡1 原始记录（默认展开预览）    │  │
│  └───────────────────────────────┘  │
│  ┌───────────────────────────────┐  │
│  │ 卡2 追加笔记                  │  │
│  └───────────────────────────────┘  │
│  ┌───────────────────────────────┐  │
│  │ 卡3 AI 流式/完成卡            │  │
│  └───────────────────────────────┘  │
├─────────────────────────────────────┤
│ 底部常驻输入条：                        │

```

### 4.2 智能卡片容器（SmartCard）

所有卡片共用统一壳，内容区委托给类型组件：

```
SmartCard
├─ CardHeader（类型图标 + 来源徽标[初始/追加/AI] + 时间 + 展开按钮 + 菜单）
├─ CardBody  （按 BlockType 委托）
└─ CardFooter（上下文操作：AI 处理/转待办/复制/分享/删除，可折叠）
```

行为：
- **折叠策略**：text 卡内容 > 500 字默认折叠，展开时全卡片内展开（不占屏动画，移动端可选全屏）。
- **来源徽标**：`initial` 显示"原始"，`appended` 显示"追加"，`ai` 显示"AI"。
- **卡片操作菜单**：AI 处理（模板选择）、转为待办（todo 卡）、复制、分享、删除（软删）。

### 4.3 卡片点击路由表（策略模式）

```dart
abstract class CardAction {
  Future<void> execute(BuildContext context, CanvasController canvas);
}

class MarkdownEditAction implements CardAction { ... }   // text / code
class EntityEditAction   implements CardAction { ... }   // smartEntity
class TodoToggleAction   implements CardAction { ... }   // todo（原地）
class ImagePreviewAction implements CardAction { ... }   // image
class ChartViewAction    implements CardAction { ... }   // chart
class AiStreamAction     implements CardAction { ... }   // 继续/停止/转正

final cardActionRouter = <BlockType, CardAction>{ ... }; // 注册表，新增类型只改这里
```

文件：`lib/features/smart_canvas/services/card_action_router.dart`。单测覆盖"类型 → 动作"映射。

### 4.4 追加笔记流

底部输入条（复用快速收集面板组件，抽成通用 `AppendInputBar`）：

1. 输入文本/选附件/选模板 → 点发送。
2. `CanvasController.append()`：新建 `Block(text, sortOrder=max+1, meta.source=appended)`，落库。
3. 若选了模板 → 触发 AI 处理（见 4.5），产物作为下一张卡。
4. 列表局部插入（不整页刷新），`diary.contentText` 聚合刷新。

语音按钮（遗留项 2）：按住录音 → STT 转文字 → 追加为 text 卡；离线/云端策略见第 8 节决策点。

### 4.5 AI 处理卡片生命周期（遗留项 1：模板 AI 真实接入）

```
卡片菜单选模板（待办/打卡/扩写/润色/会议记录/翻译）
  → 创建 aiStream Block（source=ai，streamBuffer=''，streamComplete=false）
  → AI Provider 流式返回，StreamingController 节流渲染（每 80ms 刷一帧）
  → 每 50 token 持久化 streamBuffer（断点恢复，P2.9 已有字段）
  → 完成后两种去向：
     ├─ 自动转正：aiStream → text/todo/smartEntity（保留 block id，改 type + content）
     └─ 保留为 AI 对话卡（可继续追问）
```

AI Provider 抽象（`lib/features/ai/`）：

```dart
abstract class AiProvider {
  Stream<AiChunk> streamTemplate({required String content, required AiTemplate template});
  Future<String> transcribeAudio(...);   // 遗留项 2
  Future<List<double>> embed(String text); // 遗留项 4
}
```

首期实现 `OpenAiCompatibleProvider`（base_url + api_key 配置，DeepSeek/OpenAI 通用），配置存 `flutter_secure_storage`（复用 CRM 令牌的存储模式）。模板 Prompt 表放 `lib/features/ai/prompts.dart`（纯字符串常量 + 单测快照）。

### 4.6 智能实体卡（CRM 联动）

- 展示：`EntityCard` 渲染实体摘要（名称/公司/状态徽标）。
- 原位编辑：卡片内下拉搜索（复用 `CrmEntityCache` 本地缓存，后续接 Twenty 模糊搜索）。
- 展开编辑：`EntityEditorPage` 全屏表单（联系人/公司/商机/任务字段），保存回写 Block 并标 `syncStatus=pending`。
- 点击实体卡 → `EntityEditAction` → `EntityEditorPage`。

### 4.7 同步状态接入（遗留项 3：FFI 事件流）

- `SyncController` 订阅 Rust `sync_progress_stream`（frb StreamSink 重新生成绑定）。
- 卡片右上角按 `meta.syncStatus` 显示状态点（同步中/待同步/冲突）。
- 冲突卡显示"冲突"徽标，点击进入冲突审阅（P4.2 预留入口）。
