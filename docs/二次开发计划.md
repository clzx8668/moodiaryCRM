### 1.3 关键架构差异与适配决策

文档第四节给出的是 **Rust 侧 Isar 模型**，而当前项目是 **Flutter 侧 Isar**（Dart 定义 schema，Rust 只做工具函数）。为控制风险，采用以下适配原则（已偏离文档原文，需知悉）：

1. **Isar 以 Flutter 端为唯一真相层**：`Diary`/`Block`/`CrmContactCache`/`SyncState` 等 Collection 在 Dart 侧用 Isar 定义（当前工程惯例），Rust 侧通过 FFI 收发扁平 DTO（bincode/JSON），不直接持有数据库。
2. **Rust 层职责**：同步引擎（拉/推/冲突）、AI 解析与 Embedding、向量索引抽象（VectorIndex trait + Mock）、分词/加密等纯逻辑。文档中的 Rust 模型作为同步 DTO 结构在 `rust/src/sync/` 中定义。
3. **LanceDB 按文档采用 Cargo Feature + Mock 占位**，Phase 3 前不引入原生依赖。
4. **Block 采用独立 Isar Collection（Block）**，通过 `diaryId` 关联，满足"独立表、支持单独查询"的要求，同时保留 `Diary` 现有字段以兼容上游。
5. **页面级 FAB 改造**在 Phase 2 统一做，先完成 Block/收集面板，保证每页 FAB 风格统一（圆角/阴影/主色调）。
6. **二次开发目录隔离**：所有新代码放入 `lib/features/`（或 `rust/src/` 新增模块），不散落在上游 `lib/pages/`。
7. **全局放弃 Quill 富文本（2026-08-19 用户决策）**：内容统一为 Markdown；用智能块（Notion 式）封装功能内容块（文本/待办/图片/图表/代码/智能实体/AI 流式）；历史 Delta 数据由迁移 v2→v3 自动转换。
8. **数据库 Isar → Drift（2026-08-20 用户决策）**：Isar 4.0-dev 与 Dart 3.11 工具链不兼容且无法持久升级，改用 Drift(SQLite)；IsarUtil 接口保留、内部切换；Flutter 升至 3.41.0。

## 2. 目标与范围

### 2.1 总体目标

将 Moodiary 从"日记应用"升级为"本地优先 + 智能化的轻智能终端"：

- **数据层**：全面落地 Block 协议（Markdown/结构化 JSON 双模态），历史数据自动迁移。
- **记录层**：首页快速收集面板（富文本 + 附件缩略图 + 语音入口预留）+ AI 静默意图打 Tag。
- **业务层**：日历热力图/待办/时间轴；CRM（Twenty 双向增量同步 + 自定义表格 + 业务下钻）。
- **智能层**：多知识空间 + RAG 检索 + AI 流式对话（引用溯源 + 断点恢复）。
- **工程层**：Rust 同步引擎、FFI 契约版本化、模块开关、同步日志、健康度检查、测试金字塔。

### 2.2 范围外（本期明确不做）

- 语音识别引擎接入（仅预留入口）。
- LanceDB 真实集成（Phase 3 启用 Feature）。
- iOS/macOS 真机签名与商店发布。
- 上游 Moodiary 代码大改（坚持扩展点 + 目录隔离）。

## 6. 多 Agent 开发岗位与协作协议

### 6.1 岗位设置

| 岗位 | 代号 | 职责 | 代码所有权 |
| :-- | :-- | :-- | :-- |
| 架构师 / 主协调 | `arch` | 计划、接口契约、评审、合并、冲突仲裁 | `docs/`、`AGENTS.md`、`rust/src/api/ffi_api.rs` 契约 |
| Flutter 前端工程师 | `flutter` | 页面/组件/状态管理/路由扩展 | `lib/features/**`、`lib/pages/**`（新增） |
| Rust 引擎工程师 | `rust` | 同步引擎/AI/向量/日志/FFI 实现 | `rust/src/**`（新增模块） |
| 数据层工程师 | `data` | Isar 模型/迁移/索引/搜索 | `lib/common/models/**`、`lib/persistence/**` |
| 服务端工程师 | `server` | Ktor API、Mongo 仓储、健康检查 | `server/src/**` |
| 测试工程师 | `qa` | 单元/集成测试、mock 服务、CI | `test/**`、`rust/src/test/**`、`server/src/test/**` |

### 6.2 协作规则

1. **契约先行**：跨层接口（FFI、Isar schema、REST API）必须先由 `arch` 在契约文档/接口文件中定稿，相关岗位再并行实现。
2. **目录隔离**：新代码只在各自所有权目录内新增/修改；修改上游文件需在 PR 说明中标注"侵入上游"并给出理由。
3. **分支策略**：`develop` 为集成分支；每个任务开 `feat/<任务ID>` 分支（如 `feat/P1.1-block-model`）；禁止直接 push `develop`。
4. **提交规范**：`<type>(<scope>): <subject>`（type: feat/fix/refactor/test/docs/chore）。
5. **测试门禁**：提交前必须 `cargo test`（Rust 岗位）、`flutter analyze`（Flutter 岗位）、`gradlew test`（server 岗位）全绿；覆盖率按第 5 节。
6. **并行原则**：无文件冲突的任务并行；共享契约文件的实现拆成"契约定稿→分头实现→联调"三步。
7. **每日对齐**：主协调汇总进度到 `docs/开发进度.md`，阻塞超 1 小时上报。

### 6.3 岗位启动命令

各岗位 agent 启动时携带任务书（本文档对应任务行 + 契约引用），遵循本协议，完成后回报主协调。
