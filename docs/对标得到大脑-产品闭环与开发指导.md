# 对标得到大脑：产品闭环与开发指导（总纲）

> 状态：**草稿 v0.1（待评审）**　|　日期：2026-09-05

## 0. 一句话定位

> 得到大脑是“云端大众知识管理”；moodiaryCRM 是“本地专业用户的 AI 第二大脑 + CRM”。

两者产品骨架同构：**随手记录 → AI 整理 → 主动思考 → 智能找回 → 变成作品 → 落地行动**。
对标不是把得到大脑抄一遍，而是把它在“捕获、整理、作品化、主动”四条线上的产品化深度，
补到我们自己的主循环上；CRM 不是对标障碍，而是我们闭环末端的差异化“行动层”。

## 1. 对标基线（得到大脑，2026-08 版）

> 信息源：App Store / yesky / doc.biji.com / 量子位智库访谈 / @getnote CLI 与 MCP 文档。

### 1.1 产品三件事（创始人方法论）

| 环节 | 内涵 | 我们的对应动作 |
| :-- | :-- | :-- |
| 好记 | 多模态捕获，AI 自动整理成“一篇干净笔记” | G0/G1：入口与捕获补齐 |
| 好找 | 关键词 + 自然语言，标注来源 | G3：检索增强与聚合 |
| 好用 | 把记录变成可发布作品，进入真实产出场景 | G2：技能 + 作品层 |

创始人方法论（克制护栏，见 §8）：
“三件事之外不做”“警惕堆功能，宁把一个功能从 60 分做到 90 分”“不做纪要转脑图/PPT/图表”
“站在三个月后模型能达到的水平做交互”“人主导、AI 协作”。

### 1.2 输入层

| 能力 | 说明 | 我们 |
| :-- | :-- | :-- |
| 语音速记 | 说话→实时转写→自动润色；长录音、方言、专业词库 | 已有基础，G1 升级 |
| 会议录音 | 长录音 + 声纹/发言区分 + MARK 重点 + 自动纪要 | 暂缓 |
| 图片记录 | 拍白板/书页/PPT → OCR → 结构化笔记（智能拍书） | G1 后期 MVP |
| 链接记录 | 粘贴 URL → 抓全文 → AI 总结要点 | **G1 重点（见 §5.2）** |
| 文字输入 | 直接打字，AI 润色纠错 | 已有 |
| 文件上传 | PDF/Word/PPT → 解析入库 + 关联 | 已有附件基础，增强 |
| 追加记录 | 笔记详情继续追加文本/语音/图片/链接 | G1 补任意类型追加 |

| 能力 | 说明 | 我们真实状态 |
| :-- | :-- | :-- |
| 四大技能 | 点评 / 发芽 / 润色 / 拷问 | 润色类已有基础（去口语化/模板润色）；点评/发芽/拷问 **未做（G2）** |
| 打磨/成稿 | 把话说成可发布作品 | 未做（G2 作品层） |

### 1.5 生态与数据保真

- 多端 + 小组件 + 小程序 + CLI + MCP + Skill；
- 数据层保留“原文 / 转写 / 清洗稿”三层（CLI 提供 `note original`、`note transcript`、`note attachments`）——与我们的去口语化原文保留同思路；
- 我们是 Windows + Android、本地 Drift + 文件系统 + LAN/WebDAV 同步，**数据不出本机是差异化优势**；
- 生态扩展（CLI/MCP/小组件）放入 G4 可选。

## 4. 分支与推进策略

### 4.1 历史切点结论：不回退

- CRM 自 M1 合并起就与整套 AI 笔记基座同源，不存在“既带 AI 笔记架构又不含 CRM”的历史节点；
- v2.10.0 之前缺编辑器统一/命令面板；v2.11.0 缺日历与 extract_plan；更早节点缺全部智能基座——回退均需重做已完成工作；
- 结论：**在当前 `feat/local-crm-v1` 收尾后从 HEAD 开新分支**，用模块开关 + 首页重排收容 CRM/Obsidian，不做 git 历史回退。

### 4.2 推荐执行序

```powershell
# 1) 提交当前批次 35–37 WIP 并打 tag（如 v2.18.0+104）
# 2) 本文件评审定稿
# 3) 从收尾后的 HEAD 建分支
git checkout -b feat/align-get-brain
```

### 4.3 CRM / Obsidian 处置

- CRM：保留代码与数据，`moduleCrm` 开关默认按 G0 决策收进“更多/设置”，只做回归、不扩展；
- Obsidian：类比得到大脑的“内容源”，保留但降级入口（设置 → 数据源/Obsidian）；
- 日历/日程：Schedule 已与 extract_plan 耦合，保留为“行动层”底座。

## 5. G 系列路线

### G0 — 范式重排（纯 UI，不涉及数据迁移）

**目标**：移动端首页/捕获入口按得到大脑范式重排；PC 端维持左列表右日历。

| 任务 | 说明 |
| :-- | :-- |
| G0.1 | 移动端首页：顶部搜索框 + “聊一聊”入口 + 底部大录音按钮 + “+ 更多”捕获菜单（文字/语音/链接/图片/文件） |
| G0.2 | CRM / AI 助手 / Obsidian 入口收敛：CRM 进“更多/设置”，AI 助手保留“聊一聊”，Obsidian 进数据源 |
| G0.3 | 捕获菜单统一：与现有快速收集/语音记录页打通，不新建第二套编辑器 |
| G0.4 | PC 端只做导航一致性微调（沿用之前 PC/移动分离决策） |

验收：`flutter analyze` 0 error；`flutter test` 全绿；Windows/Android 构建冒烟。

### G1 — 捕获补齐

**目标**：让“好记”覆盖文字之外的常用入口。

| 任务 | 内容 | 优先级 |
| :-- | :-- | :-- |
| G1.1 链接采集 | URL 识别器 + LinkCaptureSkill 插件路由 + CapturedContent（平台/标题/作者/正文/图片/sourceUrl） | P0 |
| G1.2 平台一期 | 通用网页（Readability，复用 Dio）+ 公众号（UA+Referer，单篇）+ B站公开信息（标题/简介/UP主） | P0 |
| G1.3 降级兜底 | 任何平台失败 → 保链接+标题；手动粘贴正文兜底；重试一次 | P0 |
| G1.4 追加任意类型 | 详情页支持追加语音/图片/链接 | P1 |
| G1.5 移动端分享 | Android “分享到”Intent 接收 URL 进入采集 | P1 |
| G1.6 SPA 兜底 | in-app WebView 加载 + Readability 注入取回正文 | P2 |
| G1.7 图片速记 MVP | 拍照/选图 → OCR（系统/云）→ 原文保留 → 生成笔记 | P2 |

链接采集平台决策详见 §6.3。

### G2 — AI 技能与作品化

**目标**：让记录“活”起来——从“整理好的存档”变成“可继续思考、可产出作品”。

| 任务 | 内容 |
| :-- | :-- |
| G2.1 AiSkill 框架 | `AiSkill` 抽象 + 注册表；模板 Prompt 集中维护；结果一律在 AI 生成区新建 `source=ai` 块（批次 36 原则），不替换原文 |
| G2.2 点评/发芽/拷问 | 详情页技能入口：点评落 AI 区可回看；发芽可“一键新建”为笔记；拷问可逐条回答形成对话 |
| G2.3 润色/打磨成稿 | 与去口语化职责分离：去口语化=原位清洗保真；润色/打磨=派生作品文本（AI 区新块/作品草稿） |
| G2.4 作品层（WORKS） | 选中 1-N 条记录 → 选择公众号/小红书/工作汇报 → 流式起草 → 复用全局 Markdown 编辑器 → 版本归档 → 导出/分享 |
| G2.5 主动建议出口 | AiTaskQueueWorker 任务完成后推送“下一步建议”（发芽/点评/提取待办/加入知识库） |
| G2.6 个性化画像（轻量） | 设置内维护“专业词库/常用表达/偏好”JSON，注入润色与技能 Prompt |

### 6.3 链接采集平台决策（含可行性修正）

| 平台 | 一期承诺 | 实现 | 风险 | 降级 |
| :-- | :-- | :-- | :-- | :-- |
| 通用网页 | 正文提取 | Readability，复用 Dio | SPA 需 JS 渲染 | 提示手动复制；二期 WebView 兜底 |
| 公众号单篇 | 标题/作者/正文 | HTTP GET + MicroMessenger UA + Referer | “环境异常/滑块”偶发 | 提示稍后重试 |
| B站 | 标题/简介/UP主（必成） | 公开 `view` 接口 | — | 字幕尽力而为，无字幕降级 |
| B站字幕（增强） | 不承诺 | player 接口 + 可选用户 Cookie | 需登录态/WBI 签名 | 降级保存基本信息 |
| 抖音 | 仅标题/链接 + 手动粘贴 | 短链跟随 + meta 提取 | 签名算法/页面结构频繁变更 | 手动粘贴正文兜底 |
| 小红书 | 不做采集承诺 | — | 需登录 Cookie | 用户手动粘贴正文 |

采集通用约束：只做单条、用户主动触发；不维护登录态池；不做批量；数据（正文/图片）落到本地附件体系并保留 `sourceUrl` 溯源。

## 8. 克制护栏（开发红线）

1. 只做“好记/好找/好用”主循环上的事；新增需求先回答“它服务哪个环节”；
2. 不做纪要转脑图/PPT/图表类“转制”功能；
3. AI 派生内容一律进 AI 生成区或作品层，原文永不静默替换；
4. 采集只做单条、低频、用户主动触发，不做登录态池与批量抓取；
5. 新字段优先进 metaJson/扩展表，避免频繁动 Drift schema；
6. 功能从 60 分到 90 分的打磨优先于横向铺新功能；
7. 站在三个月后模型能力做交互设计，不在 AI 缺陷上堆 UX 补偿。
