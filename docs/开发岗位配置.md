# 开发岗位配置（多 Agent 协同）

> 本文件定义 moodiaryCRM 二次开发的多 Agent 岗位、职责、启动任务书与协作协议。配套：[二次开发计划.md](./二次开发计划.md)。

---

## 1. 岗位总览

| 岗位 | 代号 | 模型偏好 | 工作目录所有权 | 主要产出 |
| :-- | :-- | :-- | :-- | :-- |
| 架构师 / 主协调 | `arch` | 默认 | `docs/`、`AGENTS.md` | 计划、FFI 契约、评审、合并 |
| Flutter 前端 | `flutter` | 默认 | `lib/features/**`、`lib/components/**`（新增） | 页面、组件、状态管理 |
| Rust 引擎 | `rust` | 默认 | `rust/src/**`（新增模块） | 同步引擎、AI、向量、日志 |
| 数据层 | `data` | 默认 | `lib/common/models/**`、`lib/persistence/**` | Isar 模型、迁移、索引 |
| 服务端 | `server` | 默认 | `server/src/**` | Ktor API、Mongo 仓储 |
| 测试 | `qa` | 默认 | `test/**`、`rust/src/test/**`、`server/src/test/**` | 单元/集成测试、mock |

## 2. 启动任务书模板

每个岗位 agent 的任务书必须包含：

```text
【岗位】flutter / rust / data / server / qa
【任务】P1.x <任务名>
【契约】引用的接口/模型文档或文件（FFI 契约、Isar schema、REST 文档）
【验收】明确的验收标准（构建/测试/演示）
【边界】禁止修改的目录
【回报】完成后向主协调提交：变更摘要 + 测试结果 + 待联调事项
```

## 3. 协作协议（强制）

1. 契约先行：跨层接口由 `arch` 定稿后，`flutter`/`rust`/`data` 才能并行实现。
2. 目录隔离：新代码只写各自所有权目录；侵入上游文件必须标注理由。
3. 分支：`feat/<任务ID>`，禁止直推 `develop`。
4. 测试门禁：岗位提交前必须跑通自己的测试套件。
5. 冲突仲裁：文件级冲突由最后修改者合并，逻辑级冲突上报 `arch`。

## 4. 岗位技能要点

- **flutter**：GetX 三件套（view/state/logic）；SmartCanvasPage 五个独立 Controller；页面级 FAB 统一风格（圆角/阴影/主色调）。
- **rust**：flutter_rust_bridge 2.9.0；FFI 数据结构扁平化；bincode 优先；trait 定义先于实现。
- **data**：Isar 4.0-dev.14；模型改动后必须跑 `dart run build_runner build --delete-conflicting-outputs`；迁移必须幂等 + 日志。
- **server**：Ktor 3 + Koin + Mongo coroutine driver；先写路由契约再实现。
- **qa**：Rust 用 wiremock 模拟 Twenty/WebDAV；Flutter 用 widget test + golden；server 用 ktor-server-test-host。
