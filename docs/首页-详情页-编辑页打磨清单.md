# 首页 / 详情页 / 编辑页打磨清单（对照 Twenty）

> 版本：v1.0 · 2026-08-26 · 分支：feat/local-crm-v1
> 范围：`lib/pages/home/`（首页主界面）、`lib/features/smart_canvas/`（中间详情页 SmartCanvasPage）、`lib/pages/edit/`（编辑页）。
> 原则：贴近 Twenty 的样式与交互（原位编辑、失焦自动保存、少弹窗、右侧栏/整页复用）；差异处按产品/导航合理性适配并说明。
> 说明：本文件为「分析 + 建议」清单，待确认后按 P0→P2 分步落地。

---

## 〇、结论一句话

三块的核心问题不在功能缺失，而在 **「窄背景信息密度与桌面宽幅失控」** 与 **「编辑/查看的保存语义不一致」**：

1. **首页**：桌面导航栏与移动底栏图标/文案不统一、桌面 FAB 语义与移动不一致、各 Tab 页头部没有统一的信息层级。
2. **详情页（SmartCanvasPage）**：卡片列表用 `Column` 全量构建（无虚拟化）、桌面无阅读宽度约束（卡片撑满整屏）、卡片尾部文本按钮在窄屏溢出、无「原位编辑/失焦保存」（与 CRM 已打磨风格断层）、「测试同步事件流」等开发项暴露给用户。
3. **编辑页**：**返回不保存**（双击返回直接丢弃未保存内容，是当前最大 UX 缺陷）、保存用全屏 Lottie 遮挡偏重、详情入口用 `keyboard_command_key` 图标语义不明、桌面正文无阅读宽度约束。

## 一、首页主界面（lib/pages/home/）

### 现状

- 桌面（≥600）用左侧 `NavigationRail`（6 项：Diary/Calendar/Media/CRM/AI/Setting），尾部放 `DesktopHomeFabComponent`（快速收集 / 回顶 / 新建日记 / 应用名）。
- 移动（<600）用底部 `HomeNavigatorBar`（`NavigationBar`）+ 右下 `HomeFabComponent`（展开式 FAB：新建日记）。
- 主体是 `PageView`（body 六页），`NeverScrollable`，`changeNavigator` 用 `jumpToPage`。
- `AdaptiveBackground` 在桌面给 body 加了一个「圆角卡片 + 表面色背景」的内嵌外壳；`WindowsBar` 在最外层（`MoodiaryGetPage`）。

### 与 Twenty 的差异

Twenty 是「左侧可折叠对象导航（分组 + 计数 + 拖拽 + ⌘K 命令）+ 主区对象列表 + 右侧详情」；本 App 是「日记 + CRM + AI + 设置的聚合导航」，结构不同属产品差异，不强求一致。可借鉴的是 **导航项的一致性** 与 **命令入口/搜索**。

### 建议（优先级从高到低）

| # | 项 | 现状问题 | 建议 | 优先级 | 影响面 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 1 | 导航图标/文案统一 | 桌面/移动图标混用 `Icons` 与 `Unicons`；CRM、AI 文案硬编码 `'CRM'/'AI'`，未走 `l10n` | 统一图标库（推荐 Material Icons 全系列，或 ProjectIcons 统一）；CRM/AI 文案也走 `l10n` | P1 | home_view / navigatorbar |
| 2 | 桌面/移动 FAB 语义一致 | 桌面「快速收集(⚡)+新建日记(羽毛)」与移动「展开式 FAB」按钮不一致；桌面无应用名于主区 | 两端统一为主按钮「新建/快速记录」，次级入口对齐；桌面用 tooltip，移动展开式菜单，复用同一图标与文案 | P1 | home_fab_view / home_view |
| 3 | 各 Tab 头部信息层级 | 日记页有 `SliverAppBar` 标题+一言；CRM/AI/设置各自独立头部，高度/边距不一 | 抽出统一「页面头部」规则（标题字号、搜索/操作项右对齐、间距），至少在桌面端对齐 | P2 | home_view / 各 tab 页 |
| 4 | 桌面 body 内嵌卡片 | `AdaptiveBackground` 给桌面 body 加圆角卡片，但卡片内各页再内嵌各自背景，可能层级冗余 | 统一为「最外层外壳 + 页面内只需可控内容区」，避免双重背景叠 | P2 | desktop_wrapper/background.dart |
| 5 | 命令/搜索入口 | 桌面无统一搜索/命令条；仅 CRM 有全局搜索 | 预留 `⌘K` 命令入口（跨日记/CRM 搜索）作为候选，不在本批硬做 | P2 | 跨模块（候选） |
| 6 | 导航栏拖拽手势 | `NavigationRail` 外包 `GestureDetector(onPanStart→startDragging)`，与点击/滚轮可能冲突且冗余（外层已有 WindowsBar） | 评估是否移除；保留单窗口拖拽可改为右上「标题栏空白区」拖拽 | P2 | home_view |

## 二、中间详情页 SmartCanvasPage（lib/features/smart_canvas/）

### 现状

- `Scaffold.body = Column[ Expanded(CustomScrollView(SliverAppBar + meta chips + 卡片列表)), AppendInputBar ]`。
- `SliverAppBar`：只读标题 + 返回 + [同步指示器, PopupMenu(编辑整篇/测试同步事件流)]。
- meta chips：Mood 图标 + `DateFormat.yMMMd().add_Hms()` + 标签（≤6）。
- 卡片列表：`SliverToBoxAdapter → Column`，每卡 `SmartCard`（Header + 类型内容 + Footer）。
- 空态：居中文本「暂无卡片，在下方输入框追加笔记」；加载态：转圈。
- 卡片点击按 `CardActionRouter` 路由（text/code→Markdown 全屏编辑器；smartEntity→表单；todo→勾选；image→预览；chart→对话框）。

### 与 Twenty 的差异

Twenty 的 `ShowPage` 用 `PageCardLayout`：**桌面整页 = 左列受限宽度（Summary+Fields）+ 右侧 Timeline/Tasks/Notes/Files 副列**；右抽屉/移动 = 单列卡片。卡片是「字段行原位编辑 + 失焦保存」（`RecordInlineCell`），头像 + 标题 + Added 相对时间。本 App 的卡片栈是「记录快照 + 追加 + AI 处理产物」，**查看/编辑割裂**（点击走全屏编辑器，无原位编辑）。

### 建议（优先级从高到低）

| # | 项 | 现状问题 | 建议 | 优先级 | 影响面 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 1 | 卡片列表虚拟化 | `SliverToBoxAdapter→Column` 全量构建，卡多时卡顿 | 改 `SliverList.builder` 按 `blockId` 建 key；局部刷新（`Obx` 收敛到单卡/区块） | P0 | smart_canvas_page / logic |
| 2 | 桌面阅读宽度 | 卡片撑满全屏，跨行过大 | 桌面端约束主列最大宽度（≈720px）居中；宽屏右侧可留副列/留白。移动端保持全宽 | P0 | smart_canvas_page / SmartCard |
| 3 | 卡片尾部在窄屏溢出 | Footer 一排放「AI 处理/保留对话/转待办/复制/删除」文本按钮，窄屏挤压换行 | 窄屏收敛为「更多」菜单（图标弹层）；宽屏保留文本 + 分隔线。复制/删除可保留，次要项入菜单 | P1 | card_footer.dart |
| 4 | 原位编辑/失焦保存 | 查看与编辑割裂：点卡进全屏编辑器，返回才刷新；与 CRM 已打磨的「点击字段原位编辑、失焦保存」断层 | 卡片文本/实体/待办支持「点击=查看，点标题/编辑图标=原位编辑，失焦保存」；保留「全屏编辑」作为次级入口。与 CRM `RecordInlineCell` 风格一致 | P1 | SmartCard / card_action_router / block 编辑 |
| 5 | 元信息 chips 排版 | `add_Hms` 显示到秒（噪音）；标签用带框 Chip；移动端可能拥挤 | 时间改相对时间（「3 分钟前」，Twenty `Added <relative>`）；标签改无框 `#tag` 文本流（与 CRM 详情已对齐的做法一致）；超长横向滑动 | P1 | smart_canvas_page |
| 6 | 移除开发项 | 「测试同步事件流」暴露给最终用户 | 移出更多菜单；如需保留，置于「实验室/设置」或 `kDebugMode` 下 | P1 | smart_canvas_page |
| 7 | 空态/首卡引导 | 空态仅一行文本，无引导 | 空态加图标 + 「写第一张卡片」CTA（触发 append 聚焦）；「第 N 张卡」单调场景可不做 | P2 | smart_canvas_page |
| 8 | 追加输入条 | 语音/@ 为「开发中」占位；模板 Chip 交互好 | 保留模板；语音/@ 在未接入前弱化（置灰+tooltip 已够，或移除按钮留白给输入框）；移动端确保不溢出 | P2 | append_input_bar.dart |
| 9 | 同步指示 | 仅同步中显示；断点/冲突卡有状态点但入口不明显 | 冲突卡点开给轻量冲突提示（不强制弹窗）；同步失败给可重试入口（候选） | P2 | smart_card / logic |
| 10 | AI 流式卡「转正」反馈 | 转正成功只 toast；无形态变化提示 | 转正后卡片形态变化（→text/todo）+ 轻提示即可；保持少弹窗 | P2 | smart_canvas_logic |

## 三、编辑页（lib/pages/edit/）

### 现状

- `AppBar`：居中标题（`AutoSizeTextField`）+ 返回（双击返回）+ 保存✅。
- 正文 `buildWriting`：`Stack[ 内容编辑/预览, 顶部居中(类型/计时/字数 chips) ]` + 底部 `markdownToolBar`。
- 详情（日期/天气/分类/标签/心情）通过工具栏「命令图标」打开底部弹层。
- `PopScope(canPop:false)`，双击返回才走 `handleBack`。
- 保存：`LottieModal(cat)` 全屏遮挡。

### 与 Twenty 的差异 / 自身缺陷

Twenty 的字段编辑是 `RecordInlineCell` 原位编辑、**失焦自动保存**，几乎不做整页弹窗。本编辑页仍是「显式保存 + 双击返回」，且 **返回不保存**（`handleBack` 直接 `Get.back()`，未触发保存，丢弃未保存内容）——这是当前最大缺陷。保存遮挡也偏重。

### 建议（优先级从高到低）

| # | 项 | 现状问题 | 建议 | 优先级 | 影响面 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 1 | 返回不保存（最重要） | 双击返回直接 `Get.back()`，未保存内容静默丢弃 | 改为「有未保存改动时返回先保存或确认」，对齐 CRM 失焦保存语义：标题/字段失焦即轻量落库；退出时若有改动走「保存并返回 / 放弃」。至少：双击返回前若 `hasChanges` 先自动保存 | P0 | edit_logic / edit_view |
| 2 | 保存反馈 | 全屏 `LottieModal(cat)` 遮挡偏重，图片长文保存时交互被锁 | 保存态放 AppBar（提交图标转圈/`isSaving` 禁用）+ 顶栏轻 SnackBar；保留提交前的阻塞逻辑但 UI 不整页遮罩 | P1 | edit_view |
| 3 | 详情入口语义 | 用 `Icons.keyboard_command_key` 作「日记信息」入口，语义不明 | 换 `info`/`tune` 图标 + tooltip「日记信息」；或把详情行直接上移到 AppBar 下方（懒加载） | P1 | edit_view |
| 4 | 顶部 chips 遮挡内容 | 顶部「类型/计时/字数」叠在内容区，长文滚动时可能遮挡首行 | 移到 AppBar（标题下一行）或随滚动隐藏；至少不与正文首行重叠 | P2 | edit_view / buildWriting |
| 5 | 桌面阅读宽度 | 连接宽屏内容跨行 | 桌面约束内容区最大宽度（≈760px）居中；标题/工具栏同步收窄 | P2 | edit_view |
| 6 | 字段/区块编辑一致性 | 详情行用 `AdaptiveListTile` + 尾部图标按钮；与 CRM 字段行 hover 反馈不一致 | 详情行加 hover 高亮（与 CRM 一致）；图片/媒体功能已注释掉的部分清理或恢复入口，避免死代码 | P2 | edit_view / edit_logic |
| 7 | 标题/正文失焦保存 | 标题失焦不保存（依赖显式保存） | 标题失焦做轻量 `autoSaveTitle`（只写 Diary.title + 聚合投影），正文保持显式保存（涉及资源/分词） | P2 | edit_logic |

## 四、落地顺序与验证

- **P0（必须先做，体验硬伤）**：
  1. 编辑页返回不保存 → 失焦/返回自动保存或确认（§三-1）。
  2. 详情页卡片列表虚拟化（`SliverList.builder`）+ 桌面阅读宽度（§二-1/2）。
- **P1（对齐 Twenty 风格，主要打磨）**：
  3. 详情页卡片尾部窄屏收敛 + 原位编辑/失焦保存 + 元信息相对时间 + 移除开发项（§二-3/4/5/6）。
  4. 首页导航图标/文案统一 + 桌面/移动 FAB 一致（§一-1/2）。
  5. 编辑页保存反馈轻量化 + 详情入口语义（§三-2/3）。
- **P2（锦上添花，可后续）**：空态/首卡引导、桌面应用名、命令入口、冲突入口、顶部 chips 防遮挡等。

每步落地后：`flutter analyze` 0 error、`flutter test` 全绿（基线 189）、Windows/Android 构建验证，并更新 `docs/开发进度.md`。

> 注：本环境下 `flutter analyze`/`flutter test` 首跑可能因 pub/analyzer 网络初始化较慢；实际验证在网络恢复/本地预热后执行。
